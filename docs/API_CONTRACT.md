## 1. System Architecture & Service Topology

The application is architected around two high-performance microservices:
1. **Node.js Express Gateway & Business Backend (`http://localhost:3000/api`)**:
   - Exposes RESTful endpoints for claim intake, document management, denial tracking, appeal lifecycle, and audit logs.
   - Handles multi-tenant SQLite database persistence via **Prisma ORM** (`backend/dev.db`).
   - Enforces Role-Based Access Control (RBAC) via JSON Web Tokens (JWT).
   - Manages physical file storage in `backend/uploads/` with UUID-based obfuscation.
2. **FastAPI AI Microservice (`http://localhost:8001`)**:
   - Executes clinical document text extraction and OCR chunking (`/documents/process`).
   - Runs LangGraph stateful multi-node workflows and GLM model calls (`/ai/classify`, `/ai/analyze`, `/ai/generate-appeal`).
   - Authenticated strictly via shared header token (`x-api-key: AI_SERVICE_TOKEN`).

## 2. Authentication & Authorization (RBAC)

All endpoints (except `POST /auth/login` and `GET /health`) require a valid Bearer JWT:
```http
Authorization: Bearer <jwt_token>
```

### Roles and Capabilities Matrix:
| Role | Permitted Actions |
| :--- | :--- |
| **`BILLING_SPECIALIST` / `PROVIDER`** | Create and view owned claims; upload clinical records; attach predefined clinical PDFs; trigger AI denial root-cause analysis; generate GLM grounded appeal letters; manually edit appeal text; submit letters to the reviewer queue. |
| **`REVIEWER` / `COMPLIANCE_REVIEWER`**| Access insurance review queue; adjudicate claims (`APPROVED` or `DENIED` with reason codes); review submitted appeal letters; evaluate citations; issue final approval or rejection with feedback. |
| **`ADMIN`** | Complete system access: manage user accounts, assign roles, view hospital/insurer analytics, inspect audit logs, and trigger policy document re-indexing. |

## 3. Standard Response & Error Envelopes

### 3.1 Standard Single Entity Response (200 / 201)
Controller uniformly wraps all successful entity responses in `{ data: ... }`:
```json
{
  "data": {
    "id": "cmw1qxa430000abcde",
    "claimNumber": "CLM-2026-001",
    "status": "SUBMITTED"
  }
}
```

### 3.2 Standard Paginated List Response (200 OK)
All paginated collection endpoints return data rows along with pagination metadata:
```json
{
  "data": {
    "data": [
      {
        "id": "cmw1qxa430000abcde",
        "claimNumber": "CLM-2026-001",
        "status": "DENIED"
      }
    ],
    "pagination": {
      "page": 1,
      "limit": 20,
      "total": 1,
      "totalPages": 1
    }
  }
}
```

### 3.3 Standard Error Envelope (4xx / 5xx)
Errors generated by `AppError` or validation middleware return a standardized payload:
```json
{
  "code": "NOT_FOUND",
  "message": "Claim not found.",
  "details": null,
  "requestId": 14
}
```

#### Common Error Codes:
* `UNAUTHORIZED` (401): Missing or expired JWT Bearer token.
* `INVALID_CREDENTIALS` (401): Incorrect email or password.
* `FORBIDDEN` (403): Role lacks required permission for this resource.
* `NOT_FOUND` (404): Resource ID does not exist or belongs to another tenant.
* `CONFLICT` (409): Duplicate key violation (e.g., claim number already exists).
* `VALIDATION_ERROR` (400): Request body failed Zod schema validation.
* `UPLOAD_TOO_LARGE` (413): File upload exceeded `MAX_UPLOAD_MB` limit.
* `UNSUPPORTED_DOCUMENT` (415): File type is not a valid PDF or DOCX.

### 🏥 4.3 Claims Lifecycle & Adjudication

#### `GET /claims`
Lists paginated claims accessible to the user's institution.
* **Access**: All authenticated users
* **Query Parameters**:
  * `page` (int, default: 1)
  * `limit` (int, default: 20, max: 100)
  * `status` (enum: `RECEIVED`, `SUBMITTED`, `DENIED`, `UNDER_REVIEW`, `APPEAL_DRAFT`, `SUBMITTED_FOR_REVIEW`, `APPROVED`, `REJECTED`, `APPEALED`, `PAID`, `CLOSED`)
  * `search` (string: filters by claimNumber or patientName)

#### `POST /claims`
Submits a new hospital claim.
* **Access**: `BILLING_SPECIALIST`, `PROVIDER`, `ADMIN`
* **Request Body**:
```json
{
  "claimNumber": "CLM-2026-001",
  "patientName": "Sunil Gavaskar",
  "diagnosisCode": "K80.00",
  "procedureCode": "47562",
  "amount": "75000.00",
  "currency": "INR",
  "serviceDate": "2026-10-15T00:00:00.000Z",
  "payerName": "Bharat Health Assurance",
  "insuranceOrganizationId": "org-ins-01",
  "policyNumber": "POL-98234-IN",
  "treatmentDescription": "Laparoscopic cholecystectomy for acute cholecystitis"
}
```
* **Success Response (201 Created)**: Created claim entity (`status: "SUBMITTED"`).

#### `GET /claims/:id`
Retrieves a single claim with nested `denials`, `documents`, `evidences`, `appealLetters`, and `claimReviews`.
* **Access**: Caller's organization or assigned reviewer

#### `POST /claims/:id/review`
Adjudicates a claim. Used by insurance reviewers to approve or deny claims.
* **Access**: `REVIEWER`, `COMPLIANCE_REVIEWER`, `ADMIN`
* **Request Body (Denial)**:
```json
{
  "decision": "DENIED",
  "denialCode": "AUTH-01",
  "denialExplanation": "Service requires prior authorization prior to admission.",
  "reviewComments": "Emergency authorization endorsement missing from claim packet."
}
```
* **Request Body (Approval)**:
```json
{
  "decision": "APPROVED",
  "reviewComments": "Claim documentation substantiated; approved for payment."
}
```
* **Success Response (200 OK)**: Claim review object; claim status transitions to `DENIED` or `APPROVED`.

#### `POST /claims/:id/ai/analyze-denial`
Executes GLM reasoning to analyze the root cause of the denial and prescribe evidence requirements.
* **Access**: `BILLING_SPECIALIST`, `PROVIDER`, `ADMIN`
* **Success Response (200 OK)**:
```json
{
  "data": {
    "claimNumber": "CLM-2026-001",
    "denialCode": "AUTH-01",
    "classification": "AUTHORIZATION_REQUIRED",
    "confidence": 0.96,
    "rootCause": "Prior authorization missing for urgent/emergency inpatient surgery",
    "recommendedActions": [
      "Attach Prior Authorization verification or emergency override note",
      "Draft grounded appeal letter citing IRDAI emergency admission exception"
    ],
    "requiredEvidence": [
      { "type": "AUTHORIZATION", "guidance": "Include authorization confirmation" },
      { "type": "CLINICAL_NOTE", "guidance": "Include emergency admission clinical summary" }
    ]
  }
}
```

#### `POST /claims/:id/ai/analyze-rejection`
Analyzes compliance reviewer rejection feedback on an appeal letter using GLM.
* **Access**: `BILLING_SPECIALIST`, `PROVIDER`, `ADMIN`
* **Request Body**: `{ "letterId": "letter-uuid-optional" }`

### 📄 4.4 Documents & Clinical Evidence

#### `POST /claims/:id/documents`
Uploads a physical clinical PDF/DOCX file and automatically extracts structured evidence.
* **Access**: `BILLING_SPECIALIST`, `PROVIDER`, `ADMIN`
* **Content-Type**: `multipart/form-data`
* **Form Data**:
  * `file`: Binary file (PDF or DOCX, max 10MB)
  * `type`: Evidence type (`CLINICAL_NOTE`, `IMAGING_REPORT`, `LAB_RESULT`, `ORDER`, `AUTHORIZATION`, `REFERRAL`, `TREATMENT_HISTORY`, `OTHER`)
  * `sourceDate`: ISO 8601 string (optional)
* **Success Response (201 Created)**:
```json
{
  "data": {
    "document": {
      "id": "doc-uuid-1",
      "originalName": "operative_note.pdf",
      "type": "CLINICAL_NOTE",
      "status": "INDEXED",
      "pageCount": 2
    },
    "evidenceCount": 3
  }
}
```

#### `POST /claims/:id/documents/attach-predefined`
Dynamically generates a signed standard clinical PDF buffer conforming to payer criteria and indexes evidence.
* **Access**: `BILLING_SPECIALIST`, `PROVIDER`, `ADMIN`
* **Request Body**:
```json
{
  "templateKey": "AUTHORIZATION",
  "denialId": "optional-denial-id"
}
```
* **Supported Templates**: `AUTHORIZATION`, `IMAGING_REPORT`, `LAB_RESULT`, `CLINICAL_NOTE`, `ORDER`
* **Success Response (201 Created)**:
```json
{
  "data": {
    "document": {
      "id": "doc-uuid-2",
      "originalName": "emergency-pre-authorization-CLM-2026-001.pdf",
      "type": "AUTHORIZATION",
      "status": "INDEXED"
    },
    "evidenceCount": 1
  }
}
```

#### `GET /claims/:id/documents`
Lists all documents attached to a specific claim.
* **Access**: Authenticated claim viewers

#### `GET /documents/:id/download`
Downloads the binary PDF file stream for auditing.
* **Response Headers**:
  * `Content-Type: application/pdf`
  * `Content-Disposition: inline; filename="operative_note.pdf"`

#### `GET /evidences`
Queries indexed factual evidence excerpts.
* **Query Parameters**: `claimId` (required)
* **Success Response (200 OK)**:
```json
{

    {
      "id": "ev-uuid-1",
```

### ✉️ 4.5 Grounded Appeal Letters & Review Workflow

#### `POST /claims/:id/appealletters/generate`
Generates an AI appeal letter grounded strictly in the claim's verified evidence using GLM.
* **Access**: `BILLING_SPECIALIST`, `PROVIDER`, `ADMIN`
* **Request Body**:
```json
{
  "denialId": "denial-uuid",
  "generationKey": "unique-idempotency-key"
}
```
* **Success Response (201 Created / 200 OK)**:
```json
{
  "data": {
    "id": "letter-uuid-1",
    "claimId": "claim-uuid",
    "status": "DRAFT",
    "confidenceScore": 0.95,
    "aiGenerated": true,
    "content": "Subject: Formal First-Level Appeal for Claim CLM-2026-001\n\nDear Appeals Committee,\n\nWe hereby appeal the denial (AUTH-01)... [1] ... [2]",
    "citations": [
      {
        "citationNumber": 1,
        "sourceReference": "document:doc-uuid-1#segment=segment-0001",
        "pageNumber": 1,
        "quote": "Patient presented with acute calculous cholecystitis requiring emergent laparoscopic excision."
      }
    ]
  }
}
```

#### `GET /appealletters`
Paginated query of appeal letters visible to the caller's organization.
* **Query Parameters**: `claimId`, `status`, `page`, `limit`

#### `GET /appealletters/:id`
Retrieves an appeal letter with citations and reviewer attestation logs.

#### `PATCH /appealletters/:id`
Biller manually edits letter content or assigns a reviewer.
* **Note**: Any human modification sets `aiGenerated: false` for transparency.
* **Request Body**:
```json
{
  "content": "Updated clinical justification text...",
  "expectedUpdatedAt": "2026-11-04T12:00:00.000Z"
}
```

#### `POST /appealletters/:id/submit`
Submits the appeal letter to the reviewer queue (`status: SUBMITTED_FOR_REVIEW`).

#### `POST /appealletters/:id/approve`
Reviewer approves the appeal letter, overturning the claim denial.
* **Access**: `REVIEWER`, `COMPLIANCE_REVIEWER`, `ADMIN`
* **Request Body**:
```json
{
  "reviewerComment": "Clinical evidence substantiated; pre-authorization waiver accepted under emergency criteria."
}
```
* **System Effect**:
  * AppealLetter status transitions to `APPROVED`.
  * Associated Claim status transitions to `APPROVED`.

#### `POST /appealletters/:id/reject`
Reviewer rejects the appeal draft with required clinical feedback.
* **Access**: `REVIEWER`, `COMPLIANCE_REVIEWER`, `ADMIN`
* **Request Body**:
```json
{
  "reviewerComment": "Please provide documented failure of conservative physical therapy before joint replacement."
}
```
* **System Effect**: Sets letter status to `REQUIRES_CORRECTION` and records reviewer feedback.

## 6. Audit & Compliance Guarantees

1. **Zero-PHI Logging Enforcement**:
   - `ai-service/app/observability.py` strips all patient names, prompts, and clinical notes before writing server logs.
   - `backend/src/lib/logger.js` redacts authorization headers, passwords, cookies, and email addresses.
2. **Deterministic Data Scoping (HIPAA / DPDP)**:
   - Evidence records are partitioned with strict relational foreign keys (`WHERE claimId = :claimId`). Cross-patient vector search leakage is eliminated.
3. **Immutable Audit Trail**:
   - Every claim adjudication, document upload, and appeal approval is permanently saved in the `AuditLog` table with user identity and timestamps.
